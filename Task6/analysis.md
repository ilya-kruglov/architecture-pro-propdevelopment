# Отчёт по результатам анализа Kubernetes Audit Log

**Дата анализа:** 2026-04-07  
**Аналитик:** Студент Яндекс Практикум  
**Цель:** Выявление инцидентов безопасности в кластере Kubernetes

---

## Подозрительные события

### 1. Доступ к секретам
- **Кто:** `system:serviceaccount:secure-ops:monitoring`
- **Где:** `kube-system` namespace, secret `default-token-*`
- **Почему подозрительно:** 
  - Service account `monitoring` не имеет легитимных прав на чтение секретов
  - Попытка получить токен администратора для эскалации привилегий
  - Типичная техника lateral movement в Kubernetes

### 2. Привилегированные поды
- **Кто:** `kubernetes-admin` (или пользователь с правами администратора)
- **Что создано:** `privileged-pod` с `securityContext.privileged: true`
- **Комментарий:**
  - Привилегированный под имеет доступ к узлу хоста
  - Может монтировать корневую файловую систему хоста
  - Позволяет выйти за пределы контейнерной изоляции
  - Требует немедленного удаления и расследования

### 3. Использование kubectl exec в чужом поде
- **Кто:** `kubernetes-admin` или злоумышленник с compromised credentials
- **Что делал:** Выполнение команд в поде `coredns` в `kube-system`
- **Почему подозрительно:**
  - Доступ к системному поду может дать информацию о конфигурации кластера
  - Может быть использован для сбора данных или развёртывания вредоносного ПО
  - Exec в поды без обоснованной причины — нарушение принципа минимальных привилегий

### 4. Создание RoleBinding с правами cluster-admin
- **Кто:** `kubernetes-admin`
- **К чему привело:** 
  - Service account `monitoring` получил права `cluster-admin`
  - Любой под с этим service account может управлять всем кластером
  - Создана скрытая точка персистенции для злоумышленника
- **Почему критично:**
  - Прямое нарушение политик RBAC
  - Несанкционированное повышение привилегий
  - Должно быть немедленно отозвано

### 5. Удаление audit-policy.yaml
- **Кто:** `admin` (попытка удаления из etcd)
- **Возможные последствия:**
  - Отключение аудита скрывает следы злоумышленника
  - Невозможность forensic анализа после инцидента
  - Нарушение требований комплаенса (PCI DSS, SOC2, 152-ФЗ)

## Ошибки политики RBAC

| № | Ошибка | Описание | Риск |
|---|--------|----------|------|
| 1 | Отсутствие ограничений на создание привилегированных подов | Любой пользователь может запустить `privileged: true` | Критический |
| 2 | Нет политик на `kubectl exec` в чужие namespace | Возможность выполнения команд в системных подах | Высокий |
| 3 | Отсутствие валидации RoleBinding | Создание `cluster-admin` без approval | Критический |
| 4 | Нет сегрекации сервисных аккаунтов | `monitoring` SA не ограничен в правах | Высокий |
| 5 | Аудит не защищён от удаления | Нет контроля целостности audit политики | Высокий |

---

## Что можно считать компрометацией кластера

1. **Подтверждённая компрометация:**
   - Успешное создание привилегированного пода
   - Успешное создание RoleBinding с `cluster-admin`
   - Доступ к секретам kube-system из неавторизованного SA

2. **Требует расследования:**
   - Попытки удаления audit policy
   - `kubectl exec` в системные поды

3. **Должно быть немедленно отозвано:**
   - RoleBinding `escalate-binding`
   - Привилегированный под `privileged-pod`

---

## Рекомендации

1. Немедленные действия:
    ```bash
    kubectl delete rolebinding escalate-binding -n secure-ops
    kubectl delete pod privileged-pod -n secure-ops
    kubectl delete sa monitoring -n secure-ops
    ```
2. Внедрить Pod Security Standards:
    ```yaml
    apiVersion: v1
    kind: Namespace
    metadata:
      name: secure-ops
      labels:
        pod-security.kubernetes.io/enforce: restricted
    ```
3. Настроить OPA/Gatekeeper политики:
    - Запрет привилегированных подов
    - Запрет создания RoleBinding с cluster-admin без approval
    - Валидация service account имён
4. Защитить audit политику:
    - Монтировать audit-policy.yaml из защищённой директории
    - Настроить алертинг на попытки удаления

## Вывод

Кластер Kubernetes скомпрометирован. Обнаружены множественные признаки атаки:
- Эскалация привилегий через RoleBinding
- Развёртывание привилегированных подов
- Попытки доступа к секретам

Необходимо:
1. Немедленно изолировать кластер
2. Отозвать все подозрительные привязки RBAC
3. Провести forensic анализ audit логов
4. Пересмотреть политики безопасности и RBAC
5. Внедрить Pod Security Standards и OPA/Gatekeeper
