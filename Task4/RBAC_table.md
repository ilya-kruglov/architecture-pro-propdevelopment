# Таблица ролей RBAC для кластера Kubernetes PropDevelopment

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| **cluster-admin** | Полный доступ ко всем ресурсам кластера: создание/удаление namespace, управление RBAC, доступ к секретам, управление узлами, просмотр audit-логов | `sre-team` (инженеры по эксплуатации, DevOps) |
| **security-auditor** | Чтение секретов, просмотр audit-логов Kubernetes, просмотр политик безопасности (PodSecurityPolicy, Gatekeeper), чтение любых ресурсов кластера | `security-team` (специалист по ИБ + назначенные аудиторы) |
| **namespace-editor** | Создание, изменение, удаление ресурсов (pods, services, deployments, configmaps, ingresses, jobs) ТОЛЬКО в namespace `dev-services` и `prod-services`. Доступ к секретам ЗАПРЕЩЁН | `dev-team` (разработчики функциональных команд) |
| **cluster-viewer** | Только чтение ресурсов кластера (pods, services, deployments, configmaps, nodes, namespaces, networkpolicies, jobs). Доступ к секретам ЗАПРЕЩЁН | `auditors` (внутренние аудиторы, менеджеры операционной команды) |

## Обоснование

1. **sre-team - cluster-admin**: Инженеры по эксплуатации и DevOps отвечают за всю инфраструктуру кластера, включая создание namespace, управление узлами и устранение аварий.

2. **security-team - security-auditor**: Единственный специалист по ИБ в компании должен иметь доступ к секретам и audit-логам для расследования инцидентов (например, когда клиенты видят чужие данные в ЛК).

3. **dev-team - namespace-editor**: Разработчики могут деплоить и отлаживать свои сервисы (`tenant-core-app`, `smart-home-integration`), но не должны видеть секреты (JWT-ключи, пароли БД) других сервисов.

4. **auditors - cluster-viewer**: Менеджеры и аудиторы из операционной команды могут проверять состояние сервисов, но не имеют права изменять конфигурацию или читать секреты.
